- 管理番号: #0023
- 種類: NEW（新機能）
- 対象: iOSアプリ（IOS）
- 作成日: 2026-09-28
- 関連: #0016（iOS アプリ化・引き渡し手順書）、#0022（作る途中で見つけたスマホの配置の問題）

## 概要

App Store 申請に必要なスクリーンショットを、見出し入りで5場面 × 4サイズ（計20枚）作った。この Mac の Google Chrome を画面なしで動かし、端末の大きさとタッチ操作の設定でアプリを表示して撮る。作り直せるように、撮影のスクリプトを `tools/` に置いた（追加のインストールは不要）。

## 対象ファイル

- `ios-app/screenshots/`（新規）… `iphone-6.9/` `iphone-6.5/` `iphone-5.5/` `ipad-13/` に各5枚（JPEG）
- `tools/make-screenshots.mjs`（新規）… 撮影スクリプト（`node tools/make-screenshots.mjs`。要 Node.js 22 以降と Google Chrome）
- `tools/screenshot-frame.html`（新規）… 見出しとアプリの画面を並べる台紙。場面ごとの準備（保存データ・操作）もここに書いてある
- `ios-app/岩崎さんへの引き渡し手順.md` … スクリーンショットの章を「用意済み」に書き換え
- `README.md` … ファイル構成、iOS化の状況

- JPEG（品質92）。透明部分なし（App Store は透明のある画像を受け付けない）。20枚で約4MB
- 背景・見出しの色はアプリのテーマに合わせた（5枚目はオーロラ）
- 上のステータスバー（時刻・電池）は入っていない。アプリの表示領域は、ステータスバーとホームバーの分を除いた大きさにしてある

### 撮影の仕組み（`tools/make-screenshots.mjs`）

1. スクリプトの中で小さな Web サーバーを立て、MAZE のフォルダを配る
2. Google Chrome を画面なしで起動し、DevTools Protocol（Chrome を外から操作する仕組み）で操作する。Node.js 22 に入っている WebSocket を使うので、追加のパッケージは要らない
3. 端末ごとに画面の大きさ・画素の細かさ・タッチ操作を設定し、台紙（`tools/screenshot-frame.html`）を開く
4. 台紙が場面ごとに保存データを整え（案内は既読、通算 42 クリアなど）、アプリを読み込んで操作する（最短ルートの途中まで進める・クリアする・実績画面を開くなど）
5. 撮影して保存する。Chrome の一時フォルダは最後に消す

## 確認結果

- 20枚すべてが、App Store の求める大きさ（上の表）で書き出されたことを確認
- 一覧にして見た目を確認した。見出しは読点・空白で折り返し、単語の途中では切れない
- 最初に撮ったとき、スマホでは十字ボタンが画面の外に切れていたため、アプリ側を直してから撮り直した（#0022）
